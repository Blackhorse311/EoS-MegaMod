## TIER 1 — Five systemic engine misconceptions (break most custom content)

These four/five wrong assumptions account for the majority of all bugs. Roughly 13 of 16
event scripts and major features of 5 of 7 NPCs are currently non-functional but fail
*silently* (everything is nil-guarded).

### S1. "Schedule + complete()" monitors never receive GameEvents
`_autoStartMode="Schedule"` events are created inactive; `GameEvent.*` listeners register
only while active; calling `complete()` in `onTrigger` unregisters them one frame later.
Every weekly/combat monitor is dead on arrival.
**Affected:** AldermanSystem, BlackSoxFixer, BootlegHijacking, CrewNicknames, EconomyScaling,
FedRaids, LoyaltyEvents, Moonshiners, RivalProvocations, SalBonus, SpeakeasyReputation,
TheUntouchable, ValentinesMassacre.
**Fix:** convert monitors to `_autoStartMode="Create"` with no canTrigger/onTrigger/complete
(Headlines.lua and HardModeBankroll.lua already do this correctly), or keep Schedule and call
`repeatEvent()` instead of `complete()` (vanilla: RacketEvents.lua:347).

### S2. persist{}/global vars are NOT shared across `_id` blocks
MEMORY.md's old note was wrong. ConfigBuilder attaches each top-level assignment to the
current `_id` entry only; each event/behaviour gets its own Script instance and `_vars`.
Cross-block reads silently return nil; cross-block writes log "Unknown script key" and are lost.
Only file-scope `local`s (constants/helpers) are shared, as upvalues.
**Consequences:** Renovator takes $800–1500 and never renovates; Cleaner's follow-up report
never fires; Recruiter clone-targeting no-op; Alderman offer/buyout dialogs never trigger;
BlackSox chain state lost (re-pitches forever); CrewNicknames earned dialog never shows;
SpeakeasyRep milestones never show; TheUntouchable repeats its warning; hijack/provocation
diplomacy effects dead; Moonshiners crew refs lost.
**Fix:** pass state as `WorldUtils:scheduleWithDelay(eventId, delay, slice, "key", value, ...)`
varargs — they become persisted vars on the created event (vanilla pattern, e.g.
EmpireMissionsEvents.lua:3226). Or consolidate a feature into a single `_id` block.
**Side effect to clean up:** permanently-false scheduled dialogs leak zombie event instances
into the save.

### S3. Police heat changes are cosmetic everywhere
`raiseGameEvent("onPoliceActivityEffectApplied", ...)` only feeds the GameAlerts toast UI.
The real mechanic is `precinct:addTemporaryPoliceActivity(value)` (Precinct.lua:350; negatives
OK; decays over time). Also `raiseGameEvent` takes varargs, not a table, and
`building.neighborhood`/`building.precinct` don't exist (use `building:getPrecinct()`).
**Affected:** ContractBroker Rattle (always reports "lose", $500 for nothing), Lawyer heat
reduction (charges $500, does nothing), AldermanSystem (pays $1,000 + $200/mo for a toast),
BlackSoxFixer, SpeakeasyReputation, TheUntouchable, ValentinesMassacre.
**Design note:** temp activity decays — a persistent Alderman benefit needs periodic reapply
or a proper modifier, plus a removal path when the alderman is lost.

### S4. `worldTimeCallback` dies when the registering event completes
Callbacks are owned by the script instance; completion pool-releases it and cancels callbacks.
**Affected:** BlackSoxFixer (pay $2,000, 7-day payout never arrives, chain stalls),
Moonshiners (**two crew members permanently removed**, return callback dies),
TheUntouchable (chain stalls after warning).
**Fix:** `WorldUtils:scheduleWithDelay(...)` — `_delayedEvents` is save-persisted.

### S5. Sandbox environment rules
- `client.time.worldTime` is nil in script context → use the `worldTime` special key.
  Affected: Fence.lua:217,222 + Lawyer.lua:236,241 (**cooldowns become permanent after first
  use**), Headlines.lua (every handler throws).
- `local function` helpers don't get the ctx environment → `WorldUtils`/`Utils` inside them
  are nil. Make them plain global functions (vanilla pattern). Affected: ICARep
  `ensureTargetAccessible` (also declared AFTER its caller → nil call → **contract missions
  never start**, cancellation never processes), Lawyer `applyPoliceEffect` (charges $500,
  errors, cooldown engages anyway).
- `World`, `LateRequires`, `getWorldLibs` not reachable from script ctx:
  - HardModeBankroll.lua:19 → **the $20k is never granted**. Fix: `WorldUtils:getWorldDifficulty() == 5`.
  - Headlines.lua:38 `LateRequires` → assert on every character death.
  - BootlegHijacking.lua:106/136, Moonshiners.lua:154/182/203 `getWorldLibs()` → nil call when
    player wins. Fix: `WorldUtils:addAlcoholToFaction(faction, amount, type)`.

## TIER 4 — NPC logic bugs (beyond systemics)

- **SafehouseManager**: `onSafehouseAcquired` listener dies after first trigger
  (`complete()` + auto-complete) → new safehouses never get clones. Use `disableAutoComplete()`,
  never complete. Also: `persist{}` covers only the NEXT assignment (`initialized` not
  persisted); `tostring(safehouse)` keys are memory addresses — use `iid`/`locationId`;
  no despawn on safehouse loss; re-acquired safehouse won't repopulate.
- **Save/load state loss (all NPCs)**: ad-hoc actor flags (`fenceOnCooldown`, `judgeBribed`,
  `icaContractActive`, timestamps, etc.) are not in the actor save schema → evaporate on
  reload (cooldown/bribe exploits; ICA contract desync). Use behaviour script persist vars
  or actor `memory`.
- **ICARep**: double $20k payout once mission flow is fixed (`addCashReward(20000,false,true)`
  + conversation PayOut — use `alreadyGiven=true` or drop one); no liveness check at accept
  (stale-dead target = free $20k); `onMissionFail` clears 2 of 7 fields; CancelContract
  leaves actor fields set.
- **Veterinarian**: `member.injury = nil` doesn't cure — use `member:removeState("Injury")`;
  possible double-charge in multi-heal flow (use a counter, not a boolean).
- **Lawyer**: `onAdd` resets `judgeBribed` (clones each re-sell the $1000 bribe) — use a
  faction-level `fact.*`; Legal Defense is a -$200 placebo (flag if intentional).
- **UI events calling `complete()` in onTrigger** (ICARep.lua:60, Recruiter.lua:160/193/226,
  ContractBroker.lua:104): use-after-release of pooled event while its window is open. Delete
  those calls; auto-complete handles it.
- **Recruiter**: `hireCount` dead; clone-targeting dead (S2); `recruit:setFaction(playerFaction)`
  on NPC-class actors — verify no crew-UI/faction-iteration pollution.
- All 7 spawn events: actor spawned before nil-checks — early return leaks a location-less actor.
- ContractBroker: faction selection stores index into a daily-rebuilt list — store faction id.

## Correct engine patterns (reference for the rewrite)

- Persistent listeners: `_autoStartMode = "Create"`, plain `GameEvent.*` handlers, no complete().
- Or Schedule monitors that `repeatEvent()` instead of `complete()`.
- Event-to-event data: `WorldUtils:scheduleWithDelay(id, delay, slice, "k", v, ...)` — varargs
  auto-persisted onto the new event. Delay is world-seconds.
- Heat: `building:getPrecinct():addTemporaryPoliceActivity(v)` (+ optional alert raise).
- Time: `worldTime` special key, never `client.time`.
- Difficulty: `WorldUtils:getWorldDifficulty()`.
- Alcohol: `WorldUtils:addAlcoholToFaction(faction, amount, type)`.
- RPCs: `faction.characters` / `faction:getRPCs()`; loyalty via `loyalty:get()`.
- Ratings: `faction.rating:getScore(other)`.
- Helpers in sandbox: plain GLOBAL functions (locals lose the ctx environment).
- `persist{}` covers only the next single assignment; one per var.
- Durable scalars: `fact.*`; durable actor state: behaviour script persist vars or `memory`.
- No `require` in the sandbox — cross-file shared helpers are impossible; use `_includes`/
  `_extends` for config inheritance and file-local upvalues within a file.
